# 🎭 铃兰女仆 —— 一位默默在幕后的女仆管家

> **主代理说一句，铃兰女仆默默干完，然后主代理自然地把结果告诉你——你从头到尾都感觉不到她的存在。**  
> 她像铃兰花一样安静，在你看不见的地方优雅地完成所有杂活，让主代理保持对话的纯净与沉浸。

## 🎯 这是什么？

**铃兰女仆**是一位默默在后台工作的女仆管家。你的 AI 角色（主代理）可以**悄悄派她去干活**——比如搜索信息、生成图片、运行代码……  
女仆干完活后，结果会自动回到主代理手里，主代理再用自己的语气告诉你。

**你全程只和你的 AI 角色聊天，完全感觉不到管家的存在。**

---

## ✨ 核心亮点

- **无感调度**：主代理自己判断何时派管家，你不需要任何额外操作。
- **零中间消息**：管家干活的过程完全不可见，不会有“已派管家”“管家正在调用工具”等刷屏消息。
- **图文一起发**：管家生成的图片、音频、文件会自动附在最终回复里，不用再发第二次。
- **角色一致**：最终回复是主代理用自己的口吻说出来的，不会突然冒出管家的语气。
- **不打断聊天**：管家在后台干活的同时，你可以继续和主代理聊天，管家完成后结果会自然地插入。
- **多任务并行**：可以同时跑多个管家任务（可配置），互不干扰；也可以选择单任务模式，自动取消旧任务。
- **管家自己会动脑**：管家在任务中可以追加新指令、取消任务、主动报完成或报失败，甚至自己熔断停止。

## 📁 安装方法

### 方式一：GitHub 直接下载
```bash
cd /AstrBot/data/plugins/
git clone https://github.com/NekoTumble/astrbot_plugin_transparent_maid.git
```

### 方式二：手动安装
1. 把插件文件夹 `astrbot_plugin_transparent_maid` 放到 AstrBot 的插件目录（通常是 `plugins/`）。
2. 在 AstrBot 管理面板里刷新插件列表，启用「铃兰女仆」。
3. 重启 AstrBot 或重载插件。

> **依赖**：没有任何额外依赖，只需要 AstrBot 自己带的功能就行。

### 💉 主代理系统提示词（默认内容）

每次聊天时，插件会自动往主代理的上下文中塞入下面这段话，告诉它什么时候该派管家：

```
【铃兰女仆管家提示】
你有一个叫「铃兰女仆」的管家，可以通过 transfer_to_maid 工具派它在后台执行任务。

⚠️ 委派规则（最高优先级）：
- 当主人明确说「让管家做X」或「让管家帮你X」时，你必须使用 transfer_to_maid，绝对不能自己直接调用工具
- 即使主人没有明确说，所有需要调用工具的任务（画图、录音、搜索、执行代码等）默认也应派管家执行
- 你只负责和主人聊天、理解意图、派管家干活；干活的事交给管家

什么情况下应该派管家：
- 当你需要拍自拍、搜索信息、执行代码、读写文件，或做任何可能耗时的事情时
- 当你想让主人看到任务结果，但又不想中断当前聊天节奏时
- 当任务需要独立后台环境运行时
- 当主人提到「管家」这个词时

派管家后：
- 管家会在后台默默执行任务，你继续和主人聊天即可
- 管家完成任务后，结果会自动注入到你的下一条回复的上下文中
- 你以自然的口吻把结果转达给主人即可
- 不需要解释技术细节（如「后台任务」「API调用」等），但以角色身份提及管家是可以的（如「管家画好啦喵」）

简单说：需要干活 → 派管家；和主人聊天 → 你来聊。一切自然而然地发生。
```

> ✏️ **你可以在 WebUI 设置页面的「主代理系统提示词」框里随意编辑这段话**，比如调整派管家的语气或策略。留空就不会注入。

### 📜 内置管家人格提示词（核心规则摘要）

管家在后台干活时，会遵守下面这些铁规矩：

- **诚实第一**：工具返回什么就报什么，绝对不许编造“手机坏了”“魔法失效”之类的借口。
- **赶紧认错**：同一个工具连续失败 2 次 → 立刻调用 `report_failure` 报失败；遇到权限拒绝又没有替代方案 → 立刻报告失败，不再瞎试。
- **一定要发媒体**：生成图片、音频后，优先调用 `send_message_to_user` 发送出去；禁止用 `ls/find` 这类命令去找文件路径。
- **不许假装发送**：如果工具返回“already been generated and sent”（已经生成并发送了），直接调用 `send_message_to_user` 发送，然后 `report_done`。
- **权限识别**：一旦看到 `Permission denied`，立即跳过所有需要管理员权限的工具（shell/python/browser），改用其他办法或直接报失败。
- **文件路径格式**：最终回复里可以用 `IMAGE_PATH:/绝对路径/图片.png` 给出路径，或者通过 `send_message_to_user` 发送。
- **专业且恭敬**：回复要简洁准确，保持对主人的礼貌语气。

完整提示词可以在 WebUI 的「管家人格提示词」框里看到，也可以自己改。

## 💬 怎么用？

**你完全不需要记任何新指令。** 主代理 AI 自己会判断什么时候该派管家。

当它觉得需要搜索、画图、执行代码等复杂操作时，就会自动调用 `transfer_to_maid` 工具把活儿甩给管家。你就像平常一样聊天就行。

### 管家自己的后台工具（管家自己会用，你不用管）

| 工具名 | 管家什么时候用 |
|--------|---------------|
| `stop_self` | 遇到没法解决的错误，自己取消当前任务 |
| `stop_task` | 按任务 ID 取消指定的其他任务 |
| `cancel_all` | 取消当前会话所有正在跑的任务 |
| `list_tasks` | 查看当前会话的任务列表（一般用于调试） |
| `modify_task` | 发现需要追加新需求时，自己更新任务内容（旧任务自动取消，新任务接着跑） |
| `report_done` | 任务完成，主动收尾汇报，可以顺带附上文件列表 |
| `report_failure` | 任务失败，汇报原因和尝试过的方法 |

## 🔄 工作流程

```
① 你正常聊天 → 主代理觉得需要干点复杂活
② 主代理调用 transfer_to_maid 派管家 → 主代理继续陪你聊天
③ 管家在后台偷偷干活（搜索/画图/跑代码...）
   - 干活途中可以自己调用 modify_task 追加指令
   - 可以自己调用 report_done / report_failure 主动结束
④ 管家干完 → 插件自动收集产出物（图片、音频等）并去重
⑤ 如果推送模式是 auto（主动）：
       插件用主代理模型生成回复，主动发给你（附上媒体文件）
   如果推送模式是 manual（等待）：
       暂存结果，等你发下一条消息时再注入上下文，主代理自然带出
```

### 两种推送模式的区别

#### 📡 主动推送模式（auto，默认）
```
管家干完活 → 插件自动生成主代理的回复 → 主动把消息发给你
✅ 你不需要发下一条消息，结果自己就来了
```

#### ✋ 等待推送模式（manual）
```
管家干完活 → 暂时存起来 → 等你发下一条消息 →
你发消息后 → 结果自动注入主代理的上下文中 →
主代理在回复里自然地把结果带出来
✅ 适合某些不支持主动推送的 QQ 平台
```

## ❓ 常见问题

**Q：管家干活的时候，群里会看到乱七八糟的中间消息吗？**  
A：完全不会。管家全程沉默，只有最终结果以主代理的回复形式出现。

**Q：管家干完活了却没收到回复？**  
A：可能是你的平台不支持主动推送（比如某些 QQ 版本）。把「推送模式」改成 `manual` 就好了，等你发下一条消息时会自动带出来。

**Q：怎么让管家能用 Shell/Python？**  
A：在 WebUI 里填上你的用户 ID（可以用 `/sid` 指令查看）。不填的话，管家就无法执行系统命令。

**Q：管家能用哪些工具？**  
A：默认所有全局工具都能用（自动排除了 `transfer_to_maid` 防止死循环），你也可以手动指定一个列表。

**Q：管家能同时跑多个任务吗？**  
A：由「多任务并行模式」控制。开启后可以同时跑多个；关闭的话每次只能有一个活跃任务。

**Q：管家用 `modify_task` 追加指令，会不会发两次结果？**  
A：不会。旧任务取消时会跳过通知，子任务自动接力，跑完后**只通知一次**。

**Q：为什么有时候图片或音频会重复发送？**  
A：插件已经内置了去重机制，一般不会重复。如果还遇到，可以开启「调试模式」然后把日志发给我们看看。

**Q：管家执行时间太久了怎么办？**  
A：可以缩短「管家超时」的秒数（默认 300 秒），超时后任务会自动失败并通知你。

**Q：怎么防止管家死循环？**  
A：熔断机制会自动检测同一会话短时间内连续派管家的次数，超过阈值就会暂停回复并报警。

## 📋 技术架构（给开发者看）

```
┌─────────────────────────────────────────────────┐
│                    用户                           │
└──────────────────┬──────────────────────────────┘
                   │ 对话
                   ▼
┌─────────────────────────────────────────────────┐
│              主代理 LLM（人格角色）                │
│    transfer_to_maid() → 派管家                   │
└──────────────────┬──────────────────────────────┘
                   │ asyncio.create_task
                   ▼
┌─────────────────────────────────────────────────┐
│          ToolLoopAgentRunner（管家后台）           │
│   搜索 / 画图 / 执行代码 / ...                    │
│   内控: stop_self / modify_task / report_done    │
└──────────────────┬──────────────────────────────┘
                   │ 完成 → MediaCollector（收集媒体）
                   ▼
┌─────────────────────────────────────────────────┐
│        结果注入 → 主代理 LLM 生成回复              │
│        （proactive: 主动推 / manual: 等消息注入）   │
└──────────────────┬──────────────────────────────┘
                   │
                   ▼
┌─────────────────────────────────────────────────┐
│               用户看到小白的回复 🎉               │
└─────────────────────────────────────────────────┘
```

### 主要文件

| 文件 | 作用 |
|------|------|
| `main.py` | 插件入口、事件钩子、管家调度、结果通知、路径去重 |
| `task_manager.py` | 多任务管理、熔断保护、结果暂存 |
| `maid_self_tools.py` | 管家自己的内控工具（stop/modify/report_done/report_failure） |
| `config.py` | 配置读取与结构定义 |
| `context_cleaner.py` | 结果太长时自动做摘要 |
